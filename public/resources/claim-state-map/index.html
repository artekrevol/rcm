Claim to payment state map

Identify what the sender and response prove at each step.

A claim can branch, be corrected, or receive multiple responses. Record the sender and evidence for every state instead of using one “paid” label. This educational map is not a screenshot or verification of Resolta’s current status engine.

Draft → Transmitted → Acknowledged → Accepted for adjudication → Adjudicated → Remitted → Cash reconciled
                          ↘ Rejected → Corrected attempt → new submission evidence
                                                               ↘ Denied/partial/adjusted → follow-up
StateEvidenceDoes not proveNext action
DraftClaim data or file preparedNo external transmission establishedCheck input and applicable rules
TransmittedTransport evidence of sendingNot acceptance or adjudicationMatch correlation ID and await response
AcknowledgedNamed sender reports receiptReceipt is not payer acceptanceRead acknowledgment sender and detail
Accepted for adjudicationPayer response specifically indicates acceptancePayment not establishedTrack payer processing
RejectedPre-adjudication rejection from identified senderNot necessarily an adjudicated denialCorrect using applicable requirements; preserve prior attempt
AdjudicatedPayer decision evidenceCan include denial, partial allowance or other adjustmentsReview decision and follow-up path
RemittedRemittance advice records adjudication/payment informationNot proof that cash reached the bankMatch ERA/EOB, claim/line and deposit reference
Cash receivedDeposit/receipt reconciled to the relevant remittanceNot automatically incremental Resolta benefitReconcile, attribute cautiously and close only supported items

A 277CA can report clearinghouse or payer acceptance/rejection; identify its sender before interpreting it. An 835 provides adjudication and payment details. Neither a generated EDI file nor a generic “received” label establishes payer acceptance. Sources: Stedi Acknowledgments and ERAs; Stedi Claims View.

Example, entirely illustrative: a file is generated at 09:00 and transport confirms sending at 09:05. A clearinghouse acknowledgment at 09:08 does not establish payer acceptance. If a later payer response rejects it, keep that response and correction history instead of treating the initial receipt as success. No real patient or performance data is used.
